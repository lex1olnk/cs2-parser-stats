# План работ: авторизация, отказ от PII и Docker

Рабочий документ. Источник постановки — архитектурное ревью (см. [architecture.md](architecture.md)).
Отмечай пункты по мере выполнения; каждая фаза самодостаточна и может быть смёржена отдельно.

## Три решения, которые задают рамки

| Решение | Следствие |
|---|---|
| Авторизация через Steam | `User.steamId` становится идентичностью залогиненного пользователя. Пароли/email/OAuth-провайдеры не заводим |
| Отказ от ПДн | `Profile.email` удаляется из схемы и UI. Новых PII-полей (email, телефон, ФИО, адрес) не появляется |
| Отказ от Docker | Сервисы запускаются как обычные процессы (pm2/systemd), Postgres — managed, cloudflared — системная служба |

### Отложено: формула рейтинга (сверять с FACEIT)

Решение принято — не трогаем формулу, пока не появятся матчи с FACEIT и
возможность сравнить свой рейтинг с фейситовским на одних и тех же играх.
Материал ниже — чтобы к моменту сверки не восстанавливать контекст заново.

Комментарий в миграции и подпись на странице обещают «HLTV Rating 1.0», но
считается другое. Проверено на реальном матче (vinsam10, 43 убийства / 23 смерти,
13 выживших раундов, 13 мультикилл-раундов, 36 раундов):

| | Значение |
|---|---|
| Текущая формула | **0.76** |
| Настоящий HLTV Rating 1.0 | **≈1.35** |

Причина: коэффициент `0.3591` при KPR взят из регрессии **Rating 2.0**
(`0.0073·KAST + 0.3591·KPR − 0.5329·DPR + 0.2372·Impact + 0.0032·ADR + 0.1587`),
а остальные слагаемые — из головы. В результате нормальный игрок получает ~0.5
вместо ~1.0, и весь лидерборд выглядит так, будто все играют плохо.

Настоящая Rating 1.0:

```
KillRating     = KPR / 0.679
SurvivalRating = SPR / 0.317
MultiKillRating = RMK / 1.277        RMK = (1·k1 + 4·k2 + 9·k3 + 16·k4 + 25·k5) / раунды
Rating = (KillRating + 0.7·SurvivalRating + MultiKillRating) / 2.7
```

Варианты: (а) перейти на настоящую 1.0 — потребуется хранить в
`player_rating_components_per_match` распределение раундов по числу убийств
(k1..k5), сейчас там только «раундов с 2+ убийствами»; (б) перейти на Rating 2.0
— нужны KAST и ADR, обе величины теперь есть во вьюшках; (в) оставить свою
формулу, но переименовать в UI, чтобы не выдавать её за HLTV.
Менять формулу самостоятельно не стал: это продуктовое решение.

## Переменные окружения (итог)

### `nextapp/.env`
| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Postgres connection string |
| `SESSION_SECRET` | Ключ подписи сессионной cookie (32+ байта случайных) |
| `STEAM_API_KEY` | Ключ Steam Web API для ника/аватара ([получить](https://steamcommunity.com/dev/apikey)) |
| `ADMIN_STEAM_IDS` | Список steamid64 через запятую — кто получает `isAdmin` при логине |
| `APP_URL` | Публичный origin приложения (для Steam return_to и callback-URL) |
| `DEMO_SERVER_URL` | Адрес cs-parser, по умолчанию `http://localhost:3001` |
| `PARSE_TIMEOUT_MS` | Сколько ждать разбор одной демки, по умолчанию 300000 (5 мин) |
| `INTERNAL_SERVICE_TOKEN` | Общий секрет nextapp ↔ cs-parser |

### `cs-parser/.env`
| Переменная | Назначение |
|---|---|
| `PORT` / `BIND_HOST` | Порт (3001) и интерфейс (по умолчанию `127.0.0.1`) |
| `INTERNAL_SERVICE_TOKEN` | Тот же секрет, что у nextapp |
| `CALLBACK_ORIGIN` | Разрешённый origin для callback, например `https://example.com` |

Сгенерировать секреты:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```
